# A capability path toward consequential engineering and research

This is a direction for accumulating demonstrated ability, not a hiring promise,
an exam syllabus, or a list of simultaneous courses. GPT web owns the active
lesson sequence. Work advances when prerequisites can be used; earlier skills
return in harder tasks and delayed revisits.

| Layer | Capability to develop | Evidence to make inspectable |
| --- | --- | --- |
| Programming | State, control flow, collections, functions, debugging | Personally written programs, predictions, repaired bugs, changed requirements |
| Algorithms | Correctness, complexity, data structures, search, optimization | A derived baseline, justified improvement, edge cases, unseen variations |
| Software engineering | Interfaces, tests, data handling, errors, maintainability | A useful runnable project, understandable design decisions, reproducible setup |
| Systems | Processes, networking, concurrency, storage, distributed behavior | Measured bottlenecks, failure reproduction, explicit consistency and resource tradeoffs |
| Math and ML | Linear algebra, calculus, probability, optimization, numerical computation | Derivations linked to code, training/debugging, held-out evaluation, reproducible settings |
| Research engineering | Papers, implementation fidelity, measurement, experimental design | A faithful reproduction, investigated discrepancies, baselines, uncertainty, limitations |
| Original research | A worthwhile question and a defensible contribution | Prior-work comparison, hypothesis, implementation, controlled evidence, mechanism, honest claims |

AI research may concern learning/training algorithms, architectures, efficient
inference, search/reasoning, multimodal perception, agents, world models, or the
intelligence stack of robotics. Specialization follows a concrete question and
the skills needed to investigate it. The shared foundations support movement
between those directions.

## Opportunities along the way

Strong general software roles, infrastructure and systems work, ML engineering,
research engineering, student research, and useful open-source contributions can
all build relevant skills and evidence. Evaluate an opportunity by the problems,
mentorship, ownership, and work it enables. A prestigious employer is a target;
it is not permission to begin learning or making substantive contributions.

Interview practice and practical projects should eventually support one another.
Neither a large solved-problem count nor a polished repository establishes all
the skills needed for a role. Train with the actual format and allowed tools when
an interview is scheduled.

## What belongs in a portfolio entry

1. The concrete problem and why it matters.
2. Runnable code and the assumptions under which it works.
3. Personal contribution and any help received.
4. How correctness was checked and failures investigated.
5. Tradeoffs, costs, and measured improvements when relevant.
6. Limitations and the next unanswered question.

Public claims should grow with the evidence. No placeholders, course percentages,
or setup-generated commits should be presented as independent research ability.
